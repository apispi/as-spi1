Response contracts

Capture an inferred response schema and catch breaking vs additive drift automatically.

On this pageWhat the contract capturesBreaking vs additive driftCapturing and checking a contract

A response contract catches the changes assertions miss. You never write the schema — Spi infers a compact structural description from a known-good response, stores it on the saved request, and checks later responses against it. A silently dropped field or a number that became a string is caught even when the status stays 200.

What the contract captures

From a decoded JSON response, Spi records:

  • The type of every value (string, integer, number, boolean, object, array, null).
  • For objects, the properties and which of them were required (present in the sample).
  • For arrays, a single merged item schema describing the element shape.
  • A recognisable format on strings — date-time, email, uri, or uuid — because a date field that stops being a date is a real break.

Breaking vs additive drift

When a live response is checked against the contract, Spi classifies each difference into three kinds — and only two of them break a consumer:

  • Removed (breaking) — a field the contract marked required is gone.
  • Type changed (breaking) — a field is no longer the type the contract recorded. Note that an integer still satisfies a number.
  • Added (additive) — a field appeared that the contract never described. This is reported but does not break anything.

Every difference is reported with a dotted path (e.g. $.data.items[0].id) so a drift report points at the exact field. A response conforms only when there is no breaking drift and nothing was added.

Capturing and checking a contract

  1. Send the request in the Tester until you get a representative, known-good JSON response.
  2. Infer and attach the contract to the saved request — Spi walks the response into a schema for you.
  3. Later, check a fresh response against the stored contract to see what drifted.
During a collection run, a step with a contract attached is checked automatically: breaking drift fails the step (catching silent breaks no assertion covered), while additive drift is reported without failing. A monitor therefore alerts you the moment an endpoint breaks its shape.
