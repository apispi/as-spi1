MCP testing

The full MCP suite: gateway, flight recorder, mock server, replay, firewall, and agent explorer.

On this pageCalling MCP servers (the Tester)The gateway — Spi as an MCP serverFlight recorder and relayMock serverReplay for regressionsFirewall and policyAgent explorer

Spi treats the Model Context Protocol as a first-class testing target and gives it a suite of its own. You can call MCP servers, be an MCP server, record and mock real traffic, replay it for regressions, guard it with a policy firewall, and let an agent explore a server autonomously.

Calling MCP servers (the Tester)

In the Tester, choose the MCP protocol, point at a server's Streamable HTTP endpoint, and call its tools, prompts, and resources — asserting on the results just like any other response.

The gateway — Spi as an MCP server

The inversion at the heart of the suite: every other MCP server is something agents test *with*; the gateway makes Spi the testing tool agents *use*. It is a real MCP server at:

text
POST https://apispi.com/api/gateway/tools

It speaks JSON-RPC 2.0 over Streamable HTTP, is stateless (no session is issued), and is authenticated with the same personal API key as the programmatic API — so an agent is scoped to its owner's data. Its tools are your own artefacts: run a collection, check monitors, evaluate assertions, send a guarded HTTP request.

Flight recorder and relay

The flight recorder is a relay that sits between an agent and an upstream MCP server. Configure a proxy and Spi gives you a relay URL:

text
https://apispi.com/mcp-proxy/{token}

Point your agent at that URL instead of the real server. Spi forwards each exchange upstream, records it, and returns the response — so you get a full transcript of the MCP traffic your agent actually generated. Recorded exchanges can be inspected, turned into a mock, or replayed.

Mock server

Spi can serve a mock MCP server so you can develop against a stable, offline stand-in. Its URL is:

text
https://apispi.com/mcp-mock/{token}

Like the capture endpoints it is unauthenticated — the token is the credential. You can build a mock by hand, or generate one from recorded traffic so the mock mirrors a real server's responses.

Replay for regressions

Replay takes a flight recorder's captured requests and re-runs them against a target server, diffing each new response against what was originally recorded — "record production traffic once, replay it against staging to catch regressions". A response whose shape changed (a dropped field, a changed type) is surfaced using the same contract engine. It is safe by default: a recorded call to a destructive-looking tool is skipped rather than re-executed, so replaying against a live server does not repeat side effects.

Firewall and policy

The relay can enforce an ordered policy on the traffic flowing through it — an MCP firewall. Each rule has an action and a direction:

  • action — block (stop the call) or redact (mask matching values).
  • direction — request (the agent's call) or response (the server's reply).
  • tool — an optional regex on the tool name (request side).
  • pattern — a regex; for redact it selects keys/values to mask, for a response block it triggers when the response text matches.
  • on_injection — a response rule that triggers when the built-in injection scanner flags the reply.

Rules apply in order: the first block wins and stops evaluation, while redactions accumulate. This lets you stop dangerous tool calls and strip secrets out of traffic inline.

Agent explorer

The agent explorer turns the agent loop into a discovery and red-team instrument: an AI model pursues a goal by calling a server's tools, and Spi records the path it took and the capabilities it found. In safe mode (the default) it refuses side-effecting tools, so pointing it at a real server is safe — a blocked destructive call is recorded as a *finding*, not an execution — and the discovered tool surface is run through the injection scanner as it goes.

To watch an MCP server's tool surface over time, set up an MCP drift monitor.
