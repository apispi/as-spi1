Reports and sharing

Inspection reports, shareable links, public status pages, and Postman/OpenAPI export.

On this pageInspection reportsShareable report linksPublic status pagesExporting collections

Runs in Spi produce inspection reports you can keep, compare, and — when you choose — share publicly with an unguessable link. You can also publish a status page and export collections to other tools. Browse saved reports in Reports.

Inspection reports

A collection run, a monitor run, and other inspections are saved as reports with a summary and the full result data. You can list them, open one for detail, delete them, and compare two to see what changed between runs.

Shareable report links

Share a report and Spi mints an unguessable token, giving you a public, read-only URL:

text
https://apispi.com/r/{token}

Anyone with the link can view the report without an account. You can revoke sharing at any time, which invalidates the link. Because secrets are masked wherever a run is persisted, a shared report will not leak the tokens the run used — see Environments and variables.

Public status pages

A status page publishes the health of one or more monitors at a public URL:

text
https://apispi.com/status/{token}

It is token-gated and unauthenticated, renders current status and recent uptime from monitor history, and can be enabled or disabled. It is the page you point customers or teammates at instead of answering "is it down?" by hand.

Exporting collections

A collection can be exported so it lives on outside Spi:

  • Postman — export as a Postman collection to run or share it in Postman.
  • OpenAPI 3.1 — export the REST/HTTP requests as an OpenAPI 3.1 document. Spi's {{var}} templating maps to OpenAPI's single-brace {var} path/server variables, and attached response contracts become response schemas.
OpenAPI export covers REST/HTTP requests, since the other protocols have no OpenAPI representation. Spi can also import: bring in a curl command or an OpenAPI document to create requests.
