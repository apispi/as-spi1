Importing & exporting

Bring requests in from cURL, OpenAPI, and Postman; export collections, requests, and environments back out.

On this pageImportingExportingDuplicating

Spi interoperates with the tools you already use. You can import requests from cURL, OpenAPI, and Postman, and export collections, single requests, environments, and reports back out in the formats other tools understand.

Importing

Open the Import dialog in the Tester and pick a source:

  • cURL — paste a curl command, including a browser's Copy as cURL, and Spi parses the method, URL, headers, and body straight into the tester ready to send.
  • OpenAPI 3 — paste or upload a document and each operation becomes a saved request. Optionally also create a collection holding them, and an environment with the server URL stored as {{base_url}}.
  • Postman Collection v2.x — each request becomes a saved request, folders are flattened, and you can optionally wrap them in a collection. Postman's {{variable}} syntax carries across unchanged, since Spi uses the same placeholder syntax.

A cURL command drops straight in:

bash
curl https://api.example.com/v1/users \
  -H "Authorization: Bearer {{token}}" \
  -H "Accept: application/json"
Imports are capped by your saved-request limit, and they are all-or-nothing — if a batch would exceed the limit, nothing is imported rather than a partial set.

Exporting

What you export depends on what you are exporting:

  • A collection exports as Postman v2.1 or OpenAPI 3.1 — attached assertions become Postman test scripts, or OpenAPI response schemas, respectively.
  • A single saved request exports as a code snippet from the Tester's Export menu: cURL, JS fetch, Python, or raw HTTP.
  • An environment exports as JSON and imports back the same way. Secret values are never included in the export — you re-enter them when you import.
  • An inspection report exports as JSON or Markdown.

Duplicating

To clone something within Spi rather than move it between tools, use the Duplicate action — saved requests and collections each have one, so you can fork a working request or collection and change the copy without touching the original.

Because secret environment values are dropped on export, sharing an exported environment never leaks a token — the same principle that masks secrets in shared reports.
