Recorder

A relay between an agent and an upstream MCP server that records every exchange and enforces a firewall.

On this pageCreating a recorderThe timelineThe firewall policy

The Recorder is Spi's MCP flight recorder — a relay that sits between an agent and an upstream MCP server. Point your agent at the recorder's URL instead of the real server, and every call it makes is forwarded, recorded, scanned for injection, and (optionally) filtered by a firewall policy. Open it at Recorder. It is part of the MCP testing suite.

Creating a recorder

  1. Press New recorder.
  2. Give it a name.
  3. Set the Upstream MCP server — the real server calls are forwarded to, e.g. https://mcp.example.com/tools.
  4. Optionally add firewall rules (below), then Save.

Spi gives each recorder its own relay URL of the form:

text
https://apispi.com/mcp-proxy/{token}

Copy that URL and point your agent at it in place of the server's own URL. The agent's Authorization header is passed through so upstream auth still works, but it is never stored in the recording.

The timeline

Open a recorder's Timeline to see every exchange: the method, status, duration, and time, with the full request and response when you expand a row. Exchanges flagged by the injection scanner are highlighted, and you can filter to flagged only. Two actions turn recorded traffic into more:

  • Synthesize contract — reverse-engineer the server's real contract from the observed traffic, comparing each tool's declared input schema against what was actually sent and returned (undeclared fields are flagged).
  • Replay — re-run the recorded requests against the upstream and diff each response, surfacing regressions such as a removed field or a changed type. See MCP testing.

The firewall policy

A recorder can enforce an ordered policy on the traffic passing through it. Each rule has an action (block or redact) and a direction (request or response); request rules can match a tool by regex, and rules carry a pattern regex, while a response rule can trigger on injection. Rules run in order — the first block wins, redactions accumulate — so you can stop dangerous tool calls and strip secrets out of traffic inline. The operator vocabulary is detailed in MCP testing.

Deleting a recorder makes its URL return 404s to any agent still using it. Recorded traffic can also seed a mock server, so a real session becomes an offline stand-in.
