Mocks

Serve a fake MCP server at a token URL — built by hand or seeded from recorded traffic.

On this pageThe mock URLBuilding a mock by handSeeding from a recorder

Mocks let Spi serve a fake MCP server at a URL you can point an agent at — before the real server exists, or to avoid its rate limits and cost. Open it at Mocks. It is part of the MCP testing suite.

The mock URL

Each mock is served at its own token URL. Like the other capture endpoints it is unauthenticated — the token is the credential:

text
https://apispi.com/mcp-mock/{token}

Point your agent or the Tester at that URL and it behaves like a real MCP server, answering tools/list and tools/call from the tools you defined.

Building a mock by hand

  1. Press New mock and give it a name, plus the server name and version the mock should report.
  2. Define its tools as a JSON array. Each tool has a name, a description, an inputSchema, and a response — the tools/call result the mock returns.
  3. Leave it Enabled and Save. Copy the URL from the list.
json
[
  {
    "name": "example",
    "description": "An example tool",
    "inputSchema": { "type": "object", "properties": {} },
    "response": { "content": [{ "type": "text", "text": "hello" }] }
  }
]

Seeding from a recorder

You do not have to write the tools yourself. If you have captured real traffic with a Recorder, pick it from the Seed from a recorder dropdown and press Create mock: Spi builds a mock whose tools and responses mirror what the real server actually returned. From there you can edit any tool by hand.

Disabling or deleting a mock stops its URL working. Because a mock is a stable, offline stand-in, it is the safe target to develop against — and to replay recorded traffic at.
