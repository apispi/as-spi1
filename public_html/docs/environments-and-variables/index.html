Environments and variables

Reuse values with {{variable}} placeholders, a default environment, and secret masking.

On this pageThe {{variable}} syntaxManaging environmentsThe default environmentSecrets and masking

An environment is a named set of variables. Instead of hard-coding a base URL or a token into every request, you reference it as {{name}} and let the selected environment supply the value. Switching environments — say from staging to production — re-points every request at once.

The {{variable}} syntax

Anywhere in a request — the URL, header names and values, query params, and the body — write {{variable_name}}. Just before the request is sent, Spi substitutes each placeholder with the value from the active environment.

http
GET {{base_url}}/users/{{user_id}}
Authorization: Bearer {{token}}

Variable names may contain letters, digits, underscores, dots, and hyphens. A few rules keep substitution predictable:

  • Substitution is a single pass — a value that itself contains {{...}} is not expanded again.
  • An unknown placeholder is left in place and reported as unresolved, so a typo shows up as an obviously-broken request rather than a silently empty one.
  • Only {{name}} patterns are touched, so JSON bodies that legitimately contain braces are left alone.

Managing environments

  1. Create an environment and give it a name (for example, "Staging").
  2. Add variables as key/value pairs.
  3. Select it as the active environment when you send requests or run collections.

The default environment

One environment can be flagged as the default. It is the one used when nothing else is chosen — for example the fallback for a new request. Marking a different environment as default moves that flag.

Secrets and masking

Flag a variable as secret when its value is a credential. Secret handling is built in:

  • Secret values are never sent back to the browser by the API — the field returns empty, and the "secret" flag is preserved.
  • Wherever Spi persists or echoes a resolved request — request history, and any run that becomes a shareable report — the secret value is replaced with a mask (••••••).
  • Very short values (under four characters) are not masked, because blanking every "ok" or "1" in a response would destroy the output for no real protection.
Because secrets are masked in shared reports, you can share a collection run without leaking the token it used.
