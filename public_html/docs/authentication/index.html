Authentication

Bearer, Basic, and API-key auth applied server-side, with the credential in a secret variable.

On this pageThe schemesSet it once on the environmentKeep the credential in a secret variableOAuth 2.0 client credentials

Most APIs want a credential, and hand-assembling one — remembering that Basic auth is base64 of user:password, or which header a particular service wants its key in — is busywork that goes wrong quietly. The Auth tab on a request does it for you. Spi applies the scheme server-side, when the request is sent.

The schemes

  • Bearer token — sends Authorization: Bearer <token>. If you paste a token that already starts with "Bearer", Spi does not double it.
  • Basic auth — takes a username and password and sends Authorization: Basic <base64>.
  • API key — a name and a value, sent either as a header or appended to the query string. Existing query parameters and the fragment are preserved.
  • OAuth 2.0 (client credentials) — Spi fetches the token for you; see below.
  • No auth — the default; nothing is added.

Auth applies to REST, MCP, and A2A requests, in the Tester and inside a collection run alike — the same request authenticates the same way in both. gRPC, MQTT, and AMQP carry their credentials in their own connection settings instead.

Set it once on the environment

Configuring an OAuth client on twenty saved requests is twenty places to get it wrong. Instead, set the auth on the environment (Manage → Environments → Authentication). Every request then inherits it, and switching environment switches credential along with base URL.

  • Inherit from environment is a request's default — it uses whatever the selected environment supplies, and sends nothing if the environment has none. Requests saved before this existed inherit too.
  • Setting a scheme on the request overrides the environment for that request.
  • No auth (override) sends nothing even when the environment has a credential — the opt-out for a public health check in an otherwise authenticated environment.
  • An inherited OAuth client is fetched once per run, not once per step.
Inheritance is per environment, not per host: every request that inherits sends that credential, whatever it is pointed at. If an environment mixes calls to your API and to an unrelated third party, set the auth on the requests that need it, or use No auth on the ones that do not.

Keep the credential in a secret variable

Type a literal token and it is stored on the request. Instead, put it in a secret environment variable and reference it in the Auth tab:

text
Auth → Bearer token → {{api_token}}

The request — or the environment — then holds only the placeholder. The value is substituted server-side at send time, and because it is flagged secret it is masked in request history and in any shared report. It also means one request runs against staging or production by switching environment, with a different credential each time.

OAuth 2.0 client credentials

The machine-to-machine grant, done for you. Give Spi the token URL, client ID, and client secret — plus a scope or audience if the issuer wants one — and it exchanges them for an access token and sends it as a Bearer token. No more pasting a token that expires an hour later.

  • The token is cached until shortly before it expires, so a twenty-step collection run costs one token request, not twenty. A different client, scope, or audience is a separate token.
  • Credentials go to the token endpoint as HTTP Basic by default (what RFC 6749 prefers); switch to form body for issuers that want client_id/client_secret as fields.
  • The token endpoint is a URL you supply, so it gets the same SSRF checks and address pinning as the request target, and redirects are not followed — one would carry your client secret to a host that was never validated.
  • If the token cannot be obtained, the request fails with the issuer's error (for example invalid_client). It is never sent unauthenticated — reporting back whatever the target says to an anonymous caller would be a far more confusing failure.
The Auth tab replaces any header of the same name set on the Headers tab — it is the dedicated setting, and the one the UI shows as active, so a stale hand-typed Authorization header cannot silently win. Clear the Auth tab to No auth if you want to drive the header by hand.
