Assertions

The closed operator vocabulary, how assertions pass and fail, and examples.

On this pageWhat a path can point atThe operator vocabularyHow pass and fail workExamples

An assertion is a single automated check against a response: pick a path into the response, an operator, and (for most operators) an expected value. A saved request can carry a list of assertions; when it runs, every assertion is evaluated and the request passes only if all of them pass.

What a path can point at

A path names the value to check:

  • status — the response status code.
  • time_ms — the elapsed time in milliseconds.
  • header.<name> — a response header, matched case-insensitively (e.g. header.content-type).
  • A dot path into the decoded JSON body, e.g. data.items.0.id. A leading $. is optional and array indices may be written items[0] or items.0.
  • $ (or an empty path) — the decoded body itself, for asserting on the shape of a top-level array or object.
  • body — the raw body as a whole, useful when the response is not JSON.

The operator vocabulary

The set of operators is closed and deliberately small — an open vocabulary where "contains", "includes", and "has" all mean the same thing is something no evaluator can act on. These are the only operators:

  • equals / not_equals — equality. Comparison is loose on purpose, so an expected "200" matches an integer status of 200.
  • contains / not_contains — substring (or JSON-encoded substring) test.
  • matches — a regular expression. Delimiters are optional: both /foo/i and a bare foo work.
  • exists / not_exists — whether a value is present at the path. These take no expected value.
  • greater_than / greater_or_equal / less_than / less_or_equal — numeric comparison.
  • is_type — the JSON type of the value; expected is one of string, number, boolean, array, object, null.
  • has_length — the length of a string, or the element count of an array or object.
Every operator except exists and not_exists needs an expected value. exists and not_exists are the only ones that treat a missing value as anything other than a failure.

How pass and fail work

Each assertion reports its own result — the actual value found, whether it passed, and an error reason when it could not be evaluated (an unknown operator, a missing value, an invalid regex). Evaluation never throws: one malformed assertion is reported, not allowed to explode the whole suite. The request passes only when every assertion passes.

Examples

text
status            equals            200
header.content-type  contains       application/json
data.items        is_type           array
data.items        has_length        10
data.items.0.id   exists
time_ms           less_than         500
email             matches           ^[^@]+@[^@]+$

Assertions are also enforced during a collection run and are what a monitor checks on every scheduled run. For catching silent schema changes no assertion was written for, pair them with a response contract.
